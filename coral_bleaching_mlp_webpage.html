Part 1

What is a Multilayer Perceptron?

A Multilayer Perceptron (MLP) is the simplest form of a deep neural network and the conceptual foundation on which modern architectures are built. It processes information in one direction — from inputs, through one or more hidden layers, to an output — and learns by adjusting the strength of connections between neurons.

Each neuron computes a weighted sum of its inputs, adds a bias term, and passes the result through a non-linear activation function. We use ReLU (f(x) = max(0, x)), which is computationally efficient and avoids the vanishing gradient problem that plagued earlier sigmoid-based networks.

Depth vs. Width

Depth refers to the number of hidden layers. Deeper networks can represent increasingly abstract, hierarchical features — an intuition borrowed from how the visual cortex processes images. Width refers to the number of neurons per layer, governing how much capacity each layer has to represent complex patterns.

The Universal Approximation Theorem (Cybenko, 1989) provides theoretical grounding: a single hidden layer with sufficient neurons can approximate any continuous function. In practice, however, depth allows more efficient approximation with fewer total parameters, which is why modern deep learning favours depth over extreme width.

Training

The network learns by minimising cross-entropy loss — a measure of how wrong the predicted class probabilities are compared to the true labels. Weights are updated via backpropagation, which computes the gradient of the loss with respect to every weight using the chain rule, and Adam, an adaptive gradient descent optimiser that adjusts the learning rate individually for each parameter.

The Dataset

We use a synthetic ocean climate dataset spanning seven reef systems: the Red Sea, Great Barrier Reef, Caribbean Sea, Galápagos, South China Sea, Maldives, and Hawaiian Islands. Each of the 500 weekly records contains environmental measurements and a bleaching severity label.

Part 3

Exploring the Data — and Discovering a Problem

Before writing a single line of model code, we visualised the data. The scatter plot of SST versus pH coloured by bleaching severity revealed something important: the three classes overlap completely. There are no visible boundaries, no clusters, no gradients that a model could follow.

To test this formally, we ran a one-way ANOVA — a statistical test asking: do mean feature values differ significantly between bleaching severity groups?

from scipy.stats import f_oneway

for feat in ['SST (°C)', 'pH Level', 'Species Observed']:
    groups = [df[df['Bleaching Severity']==sev][feat].values
              for sev in ['Low', 'Medium', 'High']]
    f, p = f_oneway(*groups)
    print(f"{feat}: F={f:.3f}, p={p:.4f}")

The results were unambiguous:

💡 Key Insight

All p-values are far above 0.05. The bleaching severity labels show no statistically significant relationship to any of the measured features. This indicates the dataset is synthetic — labels were assigned independently of the environmental data. This is not a modelling problem we can solve; it is a data quality problem.

This finding shapes everything that follows. We continue the tutorial not because we expect high accuracy, but because the depth/width experiments still teach us exactly what we need to know — including how to recognise when a model has reached the limits of what the data can tell it.

Part 4

Preprocessing: Getting Data Ready for an MLP

MLPs require numerical inputs and are sensitive to the scale of those inputs. Our preprocessing pipeline has four steps:

1. Drop missing labels. We remove the 150 rows where Bleaching Severity is NaN, leaving 350 usable samples.

2. Encode the target. Scikit-learn's LabelEncoder maps our string labels to integers: High→0, Low→1, Medium→2 (alphabetical order).

3. Feature scaling. This is the most critical step. Consider that Longitude ranges from −155 to +148, while pH ranges from 7.87 to 8.20. Without scaling, gradient updates during training would be dominated by the large-range features, making convergence slow and unstable. StandardScaler transforms each feature to zero mean and unit variance.

⚠ Common Mistake

Always fit the scaler on the training set only, then apply it to the test set using .transform() — never .fit_transform(). Fitting on test data would leak information about the test distribution into training, artificially inflating performance estimates.

scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)   # fit + transform on train
X_test_scaled  = scaler.transform(X_test)         # transform only on test

4. Train/test split. We use an 80/20 split with stratification, ensuring the class proportions are preserved in both sets.

Part 5

Establishing a Baseline

Before building any neural network, define the floor. A majority class classifier always predicts the most frequent label — in our case, "Low" (37.7% of samples). If our MLP cannot consistently beat this, it has not learned anything useful.

dummy = DummyClassifier(strategy='most_frequent')
dummy.fit(X_train, y_train)
baseline_acc = dummy.score(X_test, y_test)
# → 0.371

Our baseline accuracy is 37.1%. Every model result reported below must be understood relative to this number.

Part 6

Experiment 1 — The Effect of Depth

We fix the width at 64 neurons per layer and train MLPs with 1, 2, 3, 4, and 5 hidden layers. Because our dataset only has 350 labelled samples, a single train/test split would be noisy. Instead we use 5-fold cross-validation, which trains five models on different data partitions and reports the mean accuracy with a standard deviation error bar.

for d in [1, 2, 3, 4, 5]:
    arch = tuple([64] * d)   # e.g. (64, 64, 64) for depth 3
    mlp = MLPClassifier(hidden_layer_sizes=arch,
                         activation='relu', solver='adam',
                         max_iter=1000, random_state=42)
    scores = cross_val_score(mlp, X_scaled, y, cv=5)

Part 8

Results and Interpretation

Across 11 total model configurations — spanning depths 1–5 and widths 8–256 — no MLP meaningfully outperformed the majority-class baseline of 37.7%. The confusion matrix of the best model shows it defaults heavily to predicting "Low" and "Medium", with little reliable distinction between classes.

📊 The Honest Verdict

These results are not a failure of the MLP. They are a direct consequence of the dataset. The ANOVA confirmed that bleaching labels have no statistical relationship to any measured feature. No model — however deep or wide, however well-tuned — can extract signal that does not exist in the data.

What would we expect with real data?

Hughes et al. (2017) demonstrated that mass bleaching events are strongly correlated with thermal anomalies — specifically degree heating weeks, a cumulative measure of SST above the local bleaching threshold. A dataset capturing genuine SST–bleaching relationships would look very different in our experiments:

  • Accuracy well above the baseline for even shallow networks
  • A clear optimal depth beyond which overfitting sets in
  • A width sweet spot where capacity matches dataset complexity
  • Standard deviations shrinking as depth/width approach the optimum

This would give us the classic bias-variance tradeoff curve: too shallow produces underfitting (high bias), too deep produces overfitting (high variance), and the sweet spot sits in between.

Part 9

Key Takeaways

📐

Scale your features

Always apply StandardScaler before training an MLP. Fit it on train only, apply to test. Non-negotiable.

📊

Establish a baseline first

A majority-class classifier costs nothing to build. Any model that can't beat it has not learned.

🔁

Use cross-validation

On small datasets, a single split is too noisy. 5-fold CV gives you uncertainty estimates alongside accuracy.

🔍

Check your data first

ANOVA and scatter plots take minutes. A simple statistical check caught the core problem before any model was trained.

⚖️

Data quality > architecture

No depth or width compensates for a dataset where labels are unrelated to features. Garbage in, garbage out.

📖

The UAT has a catch

The Universal Approximation Theorem assumes the function exists in the data. Approximating noise is still noise.

Part 10

Ethical Considerations

Deploying machine learning in environmental monitoring is not a neutral act. Coral reefs are among the most biodiverse and threatened ecosystems on Earth, and decisions informed by predictive models carry real ecological stakes.

False negatives are costly. A model that predicts "Low" severity when the true severity is "High" could delay conservation interventions — emergency cooling, reduced tourist disturbance, targeted coral rescue — by days or weeks that matter. Model uncertainty should always be communicated to decision-makers, not buried in a single predicted label.

Geographic bias limits generalisability. A model trained on seven reef systems cannot be assumed to generalise to the full diversity of the world's reefs. The Great Barrier Reef, the Red Sea, and the Caribbean have different species compositions, thermal histories, and local stressors. Deploying a model beyond its training distribution without validation is irresponsible.

Synthetic data should be clearly labelled. In research and teaching, using synthetic datasets is legitimate — but they must be flagged as such. Presenting synthetic results as if they reflect real ecological relationships could mislead other researchers or policymakers.

Data collection ethics matter too. Gathering real reef data requires underwater surveys, remote sensing, and water chemistry sampling, all of which must follow ethical marine research protocols that minimise physical disturbance to the ecosystems being studied.
